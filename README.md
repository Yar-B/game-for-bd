# Квест находок

Небольшая браузерная игра-квест для праздника: 12 карточек на экране, за
каждой — секретный код, загадка и приз, спрятанный физически в комнате.
Работает офлайн-по-сути — без бэкенда, весь прогресс хранится в
`localStorage` браузера.

## Как устроена игра

- На экране сетка из 12 карточек-слотов (3 в ряд, 4 ряда). Карточки заранее
  ни к каким призам не привязаны — это просто пронумерованные плитки.
- Игрок находит физический код (бумажка, стикер и т.п. — вне приложения),
  нажимает на любую закрытую карточку и вводит код.
- Если код верный, он «сгорает» (больше не сработает повторно), а к нажатой
  карточке привязывается **следующая по порядку** загадка из заранее
  заданного списка — независимо от того, на какую именно карточку нажал
  игрок. Порядок открытия загадок жёстко задан и не зависит от выбора
  карточек.
- Открыв загадку, игрок идёт искать приз в комнате. Найдя его, нажимает
  «Нашёл!» → подтверждает («Точно?» → «Точнее некуда!») → видит картинку
  приза.
- Счётчик наверху показывает «Найдено N из 12». После двенадцатого приза
  показывается финальное поздравление.

## Стек и почему так

- **React + TypeScript + Vite**, без роутера — одностраничное приложение,
  экран/модалки переключаются через локальный state.
- Стили — **обычный CSS**, без CSS-фреймворков и без CSS Modules. Причина
  выбора: у проекта всего 7 компонентов с некликающимися друг с другом
  именами классов, поэтому изоляция через CSS Modules не даёт ощутимой
  пользы, зато требует дополнительной настройки сборки. Вместо этого стили
  разложены по файлам рядом с компонентами (`Card.css`, `CardGrid.css`,
  `LoadingScreen.css`) плюс общий `index.css` для переменных темы, модалок
  и кнопок — а называние классов по паттерну `.card__inner`,
  `.modal-dialog` и т.п. само по себе исключает коллизии. Так проще
  редактировать вёрстку руками, не разбираясь в хешированных именах классов.
- Стейт-машина игры целиком инкапсулирована в хуке `useGameState`
  (`src/hooks/useGameState.ts`): чтение/запись `localStorage`, проверка
  кода, переходы статусов. Компоненты — чисто презентационные.
- Из зависимостей — только `react`, `react-dom`, `typescript`, `vite`,
  `@vitejs/plugin-react`, `gh-pages`, плюс `@types/react` и
  `@types/react-dom` — это официальные пакеты с типами для React (без
  собственного рантайм-кода), без них строгий TypeScript не скомпилирует
  JSX.

## Установка и запуск

Нужен **Node.js 18 или новее** (лучше 20+) — Vite 5 не запускается на Node
16 и старше: вместо понятной ошибки версия падает с
`TypeError: crypto$2.getRandomValues is not a function` при старте
`npm run dev`. Если пользуешься `nvm`, в проекте есть файл `.nvmrc`, просто
выполни `nvm use` в папке проекта (или `nvm install`, если такой версии ещё
нет) перед `npm install`.

```bash
nvm use   # если используешь nvm — подхватит версию из .nvmrc
npm install
npm run dev
```

Откроется адрес вида `http://localhost:5173`. Для проверки мобильной вёрстки
удобнее всего открыть DevTools → Toggle device toolbar (Chrome) или зайти на
этот адрес с телефона в одной Wi-Fi сети (`npm run dev -- --host`).

Сборка для продакшена:

```bash
npm run build
```

Проверить собранную версию локально:

```bash
npm run preview
```

## Как заменить контент

Все загадки, коды и пути к картинкам живут в одном файле:

**`src/data/initialData.ts`**

1. **Загадки.** В массиве `initialPrizesList` у каждого приза (`id: 1..12`)
   поменяй `mysteryText` на реальный текст подсказки. Порядок элементов в
   массиве — это порядок, в котором загадки будут открываться игрокам,
   независимо от того, по каким карточкам они кликают.
2. **Коды.** В массиве `initialCodesList` — 12 строк, каждая ровно из 6
   цифр (`'104729'`, а не число `104729` — иначе потеряются ведущие нули).
   Любой код подходит к любой карточке, порядок кодов в массиве значения не
   имеет.
3. **Картинки.** В `imagePath` у каждого приза указан относительный путь
   вида `images/prize-01.svg`. Картинки нужно положить в папку
   `public/images/` с именами `prize-01`…`prize-12` (расширение может быть
   любым — `.jpg`, `.png`, `.svg`, главное поправить `imagePath` под
   реальное имя файла). Сейчас там лежат SVG-плейсхолдеры — квадрат с
   номером, — чтобы приложение работало «из коробки» до того, как ты
   подставишь настоящие фотографии призов.

**Важно:** данные из `initialData.ts` попадают в игру только при первом
запуске на конкретном устройстве (когда в `localStorage` ещё ничего нет).
Если правишь файл на уже начатой игре — сбрось прогресс (см. ниже), иначе
устройство продолжит использовать старые данные, сохранённые в браузере.

## Публикация на GitHub Pages

Сайт будет жить по адресу `https://<твой-логин>.github.io/<репозиторий>/`
— то есть в подпапке, а не в корне домена. Поэтому важно правильно
выставить `base` в конфиге сборки.

### Шаг 0. Создать репозиторий и запушить код

```bash
git init   # если ещё не инициализирован
git add .
git commit -m "Первая версия квеста"
git branch -M main
git remote add origin https://github.com/<твой-логин>/<репозиторий>.git
git push -u origin main
```

### Шаг 1. Прописать `base` в `vite.config.ts`

Открой `vite.config.ts` и замени строку `base: '/holiday-quest/'` на своё
имя репозитория, например:

```ts
export default defineConfig({
  base: '/my-quest-repo/',
  plugins: [react()],
});
```

Имя должно **точно** совпадать с названием репозитория на GitHub, включая
регистр, и с косыми чертами по краям.

### Вариант A — деплой руками через `gh-pages`

```bash
npm i -D gh-pages
```

В `package.json` уже есть нужные скрипты:

```json
"predeploy": "npm run build",
"deploy": "gh-pages -d dist"
```

Запусти:

```bash
npm run deploy
```

Это соберёт проект и запушит содержимое `dist/` в ветку `gh-pages`. Дальше
на GitHub: **Settings → Pages → Source** выбери ветку `gh-pages` (папка
`/root`). Через минуту-две сайт появится по адресу из шага выше.

Каждый раз, когда меняешь загадки/коды/картинки, повторяй `npm run deploy`.

### Вариант B — автоматический деплой через GitHub Actions

В проекте уже лежит файл `.github/workflows/deploy.yml`:

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main, master]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - name: Install dependencies
        run: npm ci
      - name: Build
        run: npm run build
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

На GitHub: **Settings → Pages → Source** выбери **GitHub Actions** (не
ветку). Дальше при каждом пуше в `main`/`master` сайт будет пересобираться
и выкладываться автоматически — руками `npm run deploy` запускать не
нужно.

### Типичные грабли

- **Белый экран после публикации.** Почти всегда неверный `base` в
  `vite.config.ts` — проверь, что там точное имя репозитория с косыми
  чертами по краям (`/repo-name/`), а не `/` и не пустая строка.
- **Картинки не грузятся (404).** Убедись, что в `imagePath` пути
  относительные (`images/prize-01.svg`, без `/` в начале) — они собираются
  через `import.meta.env.BASE_URL`, который автоматически учитывает
  `base`. Абсолютный путь вида `/images/x.jpg` на GitHub Pages сломается,
  потому что реальный адрес файла — `/<repo>/images/x.jpg`.
- **Видна старая версия после деплоя.** Обычно это кеш браузера — сделай
  жёсткое обновление (Ctrl/Cmd+Shift+R) или открой в приватном окне. На
  телефоне иногда помогает просто закрыть вкладку и открыть заново.

## Сброс прогресса

Для тестирования у организатора есть скрытая кнопка сброса: **долгое
нажатие (3 секунды) на заголовок «Квест находок»** на главном экране.
Она очищает `prizesList` и `codesList` в `localStorage` и перезагружает
страницу — игра возвращается к состоянию «из коробки» (заново читает
`initialData.ts`).

Если нужно снести прогресс без интерфейса — можно вручную открыть DevTools
конкретного браузера и выполнить `localStorage.clear()` в консоли, либо
удалить ключи `prizesList` и `codesList`.

## Заметка организатору

Прогресс хранится в `localStorage` — то есть привязан к конкретному
браузеру на конкретном устройстве. Игра рассчитана на **один общий
телефон или планшет**, который ходит по рукам всех игроков. Если открыть
игру на другом устройстве или в другом браузере — прогресс не перенесётся,
игра начнётся заново. Также приватный/инкогнито-режим и очистка данных
браузера сотрут прогресс.
